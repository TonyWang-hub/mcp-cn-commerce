## 公开包的自动检查

维护者可以在 Python 3.11+ 环境执行，无需安装 Pro 或访问网络：

```bash
python scripts/check_public_boundary.py --root .
```

已有构建工具的项目环境完成构建后，验证即将安装或上传的文件：

```bash
python -m build
python scripts/check_public_boundary.py --root . --dist dist
```

检查包括：

- 源码不含已知私有命名空间目录；公开运行模块和工具脚本不静态导入 Pro/商业 Client，常见字面量动态导入也会被拒绝。
- 项目、构建与可选依赖、锁文件，以及制品生成的依赖元数据不得引用私有发行包；常见别名 Git URL 同样检查。
- wheel 仅允许 `shared`、`servers` 与 Core 发行元数据；sdist 按公开源码目录白名单检查。私有目录、未知运行命名空间、错误入口点、路径穿越、链接和重复成员会失败。
- `--dist` 要求同时提供 wheel 与 sdist，避免将空目录当作验收通过。检查只读归档，不解压执行其中代码。

CI 的 `public-boundary` 作业先于依赖安装；安装验收在构建后检查真实制品；发布流程在 `twine upload` 之前再次检查。这是防止误依赖、误打包的静态工程门禁，不能识别任意计算生成的导入或证明改名复制代码的来源，不能替代代码审查、密钥扫描或平台业务验收。

## 合作说明

可以只使用公开 Core，自行编排多店查询和报表。需要 Pro 时，先确认平台、权限、接收主体与部署范围，再交付对应试用包和说明并共同测试。标准种子用户内测继续免费；正式商业支持、源码改作、嵌入、OEM/再分发等权利以书面约定为准，不自动由 Core 的 MIT 或一次试用延伸至私有 Pro。

公开仓库不存放 Pro 实现或客户凭据。私有服务端的具体交付形式与运行系统按该版本的验收记录确认；编译只能提高直接阅读和逆向的成本，不代表无法复制。此说明不新增报价、收费周期、SLA 或已签约客户承诺。
