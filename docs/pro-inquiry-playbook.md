# Pro 咨询回复手册

用途：为后续 `[Pro] 咨询` 准备事实一致的回复草稿；修改本文不表示已经发送回复。更新：2026-10-10。当前逐项范围见 [SDK 能力表](sdk-integration.md#catalogue-and-evidence-status)和[工程/发布状态](release-readiness.md)。

## 0. 原则

1. 项目提供商家授权范围内的只读数据连接，不承诺所有平台或数据域当前可用。
2. 注册工具、已核合同、SDK 可调用和真实店铺验收分开说明；所有商家 `live_verified` 均为 false。
3. 优先围绕抖店、TOP 已核的订单/售后操作安排 1–2 平台 PoC。巨量/千川广告主信息和余额不等于广告报表；拼多多完整经营业务 schema 未取得，不能按历史 MCP 入口称其已接入。
4. 当前配套组合为 Pro `0.1.5b2` / Core `0.1.6` / Client `0.1.0b1`，固定 Core 源码快照 `7e10d2f`；Pro 自身 9 项工程 CI 检查通过并已合入 Pro `main`。商家 `live_verified=false`，业务验收与后台对账尚未完成，合成演练已通过，尚未提供正式客户制品；正式客户制品还需正式签名密钥、许可和接收方信息。历史 Pro `v0.1.1b1` 是旧制品，不代表当前组合。
5. 继续履行 README 的免费 Pro 种子用户内测承诺。免费内测安排不自动授予源码改作、OEM/SaaS 或再分发权利；这些另由双方条款约定。
6. Core 已公开归一化和多店日报计算，不把“多店算法”作为 Pro 独占卖点。Pro 的能力边界见 [Core / Pro 说明](core-pro-boundary.md)，只公开说明当前受支持的平台和操作状态，不复制私有实现细节。

## 1. 一次收集试点输入

先收集非秘密信息；相关材料统一汇总，不分轮索要密钥：

| 输入 | 需要确认的内容 |
| --- | --- |
| 平台与数据域 | 首选 1–2 平台；订单/退款、商品/库存、广告、账单分别列，不能只问平台名称 |
| 应用与资格 | 自用/ISV/工具型等实际应用类型、获批 API 权限包；平台许可不能用 Pro 本地授权范围代替 |
| 店铺和身份 | 店铺数量、同/跨渠道、授权主体字段、是否有多个应用 key；不让客户在 issue 粘贴 token |
| 已有样本 | 至少两页可读数据、父子订单、支付优惠、部分退/失败/跨日样本及后台对照 |
| 部署和授权入口 | 本地单商家或合作方服务、受信身份、已登记 callback/IP 白名单；HTTPS 回调需要服务端接入 |
| 生命周期与验收 | 刷新/撤销/重新授权的可用测试窗口、希望核对的报表口径及未验证项 |

应用 secret、商家 token、授权 code 和买家资料保留在受控部署侧。账号资格、官方 schema、合作方适配与真实样本分别记录，不把全部缺口概括为“只差 token”。

## 2. 回复模板 A — 简短版

> 目前可以按免费种子用户内测安排，围绕已核订单和售后范围选择 1–2 个获准店铺做只读验证。当前配套组合为 Pro `0.1.5b2` / Core `0.1.6` / Client `0.1.0b1`，固定 Core 源码快照 `7e10d2f`；Pro 自身 9 项工程 CI 检查通过并已合入 Pro `main`。商家 `live_verified=false`，真实业务验收和后台对账尚未完成，合成演练已通过，尚未提供正式客户制品；正式客户制品还需正式签名密钥、许可和接收方信息。具体操作仍需按平台权限与当前合同确认，历史 Pro `v0.1.1b1` 不代表当前组合。
>
> 若优先淘系，可以先选 TOP 订单/售后范围，并对照现有 ERP 和后台样本。巨量/千川广告报表、拼多多经营接口合同等仍有缺口。密钥和商家 token 留在你的受控部署侧，无需发到 issue。

## 3. 回复模板 B — 技术边界版

> Core 提供显式凭证的只读 SDK、平台 MCP 入口、归一化和多店日报计算；Pro 面向获准场景提供相应授权管理、持续采集和报告能力。平台与操作范围以当前能力表和应用授权为准，工具入口或平台名称不代表所有数据域已经可用。
>
> 当前优先验证抖店、TOP 已核的订单/售后只读范围；京东已核订单和售后专项，但不等于完整退款采集。拼多多经营 SDK 读取仍关闭，小红书持续采集和退款时间字段、快手授权主体、微信共享组件跨 tenant 委托等边界仍需补证。巨量/千川广告报表、商品、库存、物流、评价、营销和账单等不按工具数量整体承诺。
>
> 当前 Pro `0.1.5b2` / Core `0.1.6` / Client `0.1.0b1` 组合固定 Core 源码快照 `7e10d2f`，已合入 Pro `main`，自身 9 项工程 CI 检查通过。该工程状态不等于商家业务验收：`live_verified=false`，真实接口样本与后台对账尚未完成，合成演练已通过，尚未提供正式客户制品。可以先确认接收主体、部署方式、平台权限和限定样本，再确定试点通过标准。正式商业集成、OEM/SaaS、源码改作、再分发及支持范围按书面条款确认，免费内测不自动授予这些权利。

## 4. 演示与验收衔接

无需平台授权的演示只使用 `templates/` 中的模拟数据，并在输出写明“模拟数据，不证明真实平台可用”。广告/评价/库存等分析模板不能当作对应 API 已接通的展示。

真实 PoC 使用商家已有且获准的只读样本。逐项记录授权主体、方法、窗口/分页、实际金额/日期、后台核对、刷新/撤销/重新授权；不能为凑样本擅自下单、退款或改店铺配置。缺少两页或跨日样本时将相应项写成“未执行”，不拿模拟响应补签。

完成后回复限定在实际验证的应用、店铺、操作和样本。报告是已观测记录的汇总；不能把观察净额称作银行到账、利润或完整资金结算。
