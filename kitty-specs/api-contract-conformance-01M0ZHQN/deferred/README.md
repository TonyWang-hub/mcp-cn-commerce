# 待重建平台（暂缓，供后续 mission 使用）

本目录下的 WP 定义**不属于当前 mission**，已移出 `tasks/` 以免进入校验与实施循环。

移出原因：这四个平台的 endpoint 存在率过低或涉及整套网关换代，性质是「按真实接口重建」而非「修契约」，与当前 mission 收窄后的目标（把底子好的平台修到真能调通）不同：

| 平台 | 存在 / 总数 | 重建原因 |
|---|---|---|
| 抖店（WP06） | **0 / 20** | 成片域名幻觉；8 个能力平台不对三方开放 |
| 京东（WP08） | **0 / 15** | `jd.pop.*` 命名空间不存在；且 SP-API 才是现役网关，整套调用约定需重估 |
| 巨量引擎（WP03） | 2 / 18 | 需按 v3.0 project/promotion 族重建 |
| 微信小店（WP11） | 6 / 11 | 5 个不存在 + 4 个请求体编造；四者中最轻，可优先纳入后续 mission |

这些文件里的官方契约细节（签名规则、参数表、官方出处 URL、已核实的替代接口）**均为已验证成果，后续 mission 应直接复用**，不要重新调研。各平台的完整审计结论见本 mission `spec.md` §2。

当前 mission 仍会处理这四个平台的**一件事**：把它们不存在的 endpoint 对应的工具从注册中移除、并修正 README/FAQ 的对外口径（见 FR-013 / FR-014）。
