### 已下线的实体/报表接口 → 升级版替代

依据官方《升级版与原版差异说明》 `labels/7/docs/1758611573659724`（原版五层结构变四层，「计划组」对标「项目」、「营销创意」对标「营销」、「营销计划」拆分至两者）。**官方下线公告本身未指定替代**（41 条 path 的替代栏均为"-"）。

| 已下线 | 替代 |
|---|---|
| `2/campaign/get/`（获取广告组=计划组） | **`v3.0/project/list/`** |
| `2/ad/get/`（获取广告**计划** —— 非创意列表，代码 docstring 标错） | 需 **join** `v3.0/project/list/` + `v3.0/promotion/list/`（预算/出价/定向分散在两层，无 1:1 替代） |

**`v3.0/project/list/`**（doc `labels/7/docs/1740937147595776`）：`GET`，host `api.oceanengine.com`，header `Access-Token`，无签名。必填 `advertiser_id`；`filtering` 为嵌套对象需 URL-encoded JSON；**支持状态过滤** `status_first`（`PROJECT_STATUS_ENABLE/DISABLE/DONE/DELETE`）+ `status_second`；返回含 `budget`/`budget_mode`/`cpa_bid`/`roi_goal`/`pricing` 等实体属性 + `page_info{total_number,total_page}`。`page` [1,99999]、`page_size` [1,100]。⚠️ 扁平 `status` 字段官方标注"已不再维护，请使用 status_first/status_second"。

**`v3.0/promotion/list/`**（doc `labels/7/docs/1741028841006095`）：`GET`。`filtering.project_id` 是 project→unit 的下钻方式；`filtering.ids` **最多 20**；状态过滤同构；返回 `budget`/`bid`/`cpa_bid`/`roi_goal` 等。**两种分页**：`page`+`page_size`（`page_size` **≤20**，且 page×page_size **上限 10000 行**）或 `cursor`+`count`（`count` ≤20）—— **超过 1 万单元必须用 cursor**；`cursor` 不能与 `filtering.ids` 同用。默认不返回已删除单元。

### 字段级契约：已取到 ✅

## 官方契约 vs 现状

| 项 | 官方 | 现状 |
|---|---|---|
| 凭证 | HTTP header `Access-Token` | query 参数 `access_token` |
| 签名 | **完全不签名**（公共参数无 sign/sign_method/app_key/timestamp） | 发了 sign + sign_method + app_key + timestamp |
| host | v3.0 一律 `https://api.oceanengine.com`（487 篇文档 100% 如此） | `https://ad.oceanengine.com/open_api/` |

# 第二部分：报表迁移 v3.0（原 WP04，因与本 WP 改动同一文件而合并）
# Work Package Prompt: WP04 – 巨量引擎-报表迁移-v3.0

实现 FR-005，覆盖 IC-08。**本 mission 唯一涉及业务语义重写的 WP。**

## 背景

官方公告（预通知 `changelog/1796386957503732` 2024-04-15、正式 `changelog/1798385305745562` 2024-05-07）确认一批接口于 **2024-05-06 下线**，页面已从文档站删除。本仓库命中 5 个：

`2/ad/get/`、`2/campaign/get/`、`2/report/ad/get/`、`2/report/audience/`（整组）、`2/report/creative/get/`；另 `2/report/advertiser/get/` 的 `platform_version` V1 枚举下线。

官方现存 `2/report/*` 仅剩 `site/page/`、`rta_exp/get/`、`rta_cus_exp/get/`，本仓库均未使用。

## 迁移目标

`/open_api/v3.0/report/custom/get/`（同步）+ `/open_api/v3.0/report/custom/config/get/`（查可用维度指标）；大数据量走 `custom/async_task/{create,get,download}/`。

参数结构由旧的 `fields` / `group_by` 平铺，改为 `data_topic` + `dimensions` + `metrics` 三段式，另有 `filters` / `order_by` / `start_time` / `end_time` / `page` / `page_size`。

## 关键决策（需在实现前确定并记录）

工具暴露给模型的入参签名会随之变化。**建议保持现有工具接口稳定、在内部转译到 v3.0**，以免破坏既有用法；若选择把 v3.0 表达能力透出给模型，需在 WP12 同步更新文档。

## 陷阱

官方 Java SDK 最新版（1.1.93，2026-08-12）**仍在发布** `ReportAdGetV2Api` 等已下线接口的类 —— SDK 里有类不等于接口还活着。不要以 SDK 存在性作为接口存活依据。

## 通用约束

1. 签名参与集合必须恒等于发送集合减去 `sign`（WP02 提供通用断言，必须启用）。
2. 签名与发送使用同一字符串对象；业务参数 JSON 只序列化一次并缓存。
3. 契约声明文档中每项结论标注官方出处 URL，区分「官方明文」与「推断」。
4. 官方缺失/矛盾项按 spec.md §8 处理，不得推测填充。
5. 交付需附 wire 层断言：参数名集合、传输位置、timestamp 格式。
