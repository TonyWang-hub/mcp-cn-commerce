# Work Package Prompt: WP01 – 契约测试框架与契约声明

## 目标

建立不依赖真实凭证的契约验收手段。本 WP 是其余全部 WP 的前置 —— 没有它，后续修复无法证明"符合官方文档"。

实现 FR-001、FR-002、FR-003；覆盖 IC-01。

## 交付物

### T001 — 契约声明 fixture 结构

在 `tests/contract/` 下建立每平台一份机器可读的契约声明，字段至少包含：

- `gateway`：网关地址（及备用地址）
- `system_params`：参数名 → {必填, 位置(query/body/header), 格式说明}
- `timestamp`：{语义(unix_s/unix_ms/datetime), 格式串, 时区, 容差}
- `signature`：{参与范围, 拼接形态, secret 位置, 摘要算法, 大小写, 密钥来源} 或 `null`（巨量无签名）
- `envelope`：{成功判定表达式, 错误字段名, 业务数据字段}
- `sources`：每个结论的官方 URL + `official_explicit` / `inferred` 标注

同时在 `docs/api-contracts/<platform>.md` 写人类可读版本。

### T002 — 官方签名向量断言（硬断言）

三组官方算例直接作为测试用例：

| 平台 | 输入 | 期望 |
|---|---|---|
| 淘宝 | `secret=helloworld`，官方示例参数集 | `66987CB115214E59E6EC978214934FB8` |
| 京东 | 官方示例拼接串（见 docs/api-contracts/jd.md） | `D70825340F4084360B9362B60DFD7930` |
| 拼多多 | 官方示例拼接串（见 docs/api-contracts/pinduoduo.md） | `E4DE3ED21002510DED352819E7AE6775` |

抖店无静态算例，但有官方在线签名工具 `op.jinritemai.com/docs/guide-docs/gen-sign`；在 docs/api-contracts/doudian.md 记录一组用该工具生成的输入/输出对，作为固化向量。

### T003 — wire 层参数断言工具

提供一个测试辅助（如 pytest fixture），拦截出网请求并暴露：发送的 query 参数、body、headers。据此断言：

- 参数名集合**完全等于**契约声明的期望集合（多发和少发都要失败 —— 京东多发 `format` 就是靠这条抓）
- 每个参数落在正确位置（query / body / header）
- timestamp 匹配契约声明的格式
- **签名集合 == 发送集合 − `sign`**（通用不变式，FR-002）

### T004 — 重写 `tests/test_integration.py:128-132`

现有断言要求巨量请求包含 `sign`、`sign_method`、`app_key`、`access_token` 参数，与官方契约（token 走 `Access-Token` header、完全不签名）相反。按官方契约重写：断言 header 中有 `Access-Token`，且 query 中**不含** `sign`/`sign_method`/`app_key`/`access_token`。

### 可选（默认跳过）：联网契约巡检

一个标记为 `@pytest.mark.network` 且默认 deselect 的任务，拉取六个平台的公开文档接口（见 spec.md §5.2）与本地契约声明比对，用于发现平台侧变更。**不得进入 CI 必过路径**（NFR-001）。

## 验收

- 三组官方向量为硬断言且通过
- wire 断言工具能同时捕获"多发参数"和"少发参数"两类错误
- `test_integration.py` 不再要求错误参数
- 现有 CI 全绿

## 通用约束（所有平台 WP 适用）

1. **签名参与集合必须恒等于实际发送集合减去 `sign`。** 这是当前实现最大的结构性缺陷，WP02 的框架提供了通用断言，必须启用。
2. **签名与发送必须使用同一个字符串对象**（尤其 timestamp 与序列化后的业务参数 JSON）。禁止序列化两次。
3. **每项契约结论都要在契约声明文档里标注官方出处 URL**，并区分「官方明文」与「依据充分的推断」。
4. **官方文档缺失或自相矛盾的项**，按 spec.md §8 的处理方式执行，**不得用推测填充**。
5. 不得引入对真实凭证或外部网络的 CI 依赖。
