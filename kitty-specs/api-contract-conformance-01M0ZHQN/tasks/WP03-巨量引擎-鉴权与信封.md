# Work Package Prompt: WP03 – 巨量引擎-鉴权与信封

实现 FR-004，覆盖 IC-03/IC-06。`servers/oceanengine/server.py` 当前裸用 base class。

## 官方契约 vs 现状

| 项 | 官方 | 现状 |
|---|---|---|
| 凭证 | HTTP header `Access-Token` | query 参数 `access_token` |
| 签名 | **完全不签名**（公共参数无 sign/sign_method/app_key/timestamp） | 发了 sign + sign_method + app_key + timestamp |
| host | v3.0 一律 `https://api.oceanengine.com`（487 篇文档 100% 如此） | `https://ad.oceanengine.com/open_api/` |
| OAuth | `POST https://api.oceanengine.com/open_api/oauth2/access_token/`（接口参考页 + 官方代码示例 + 两个官方 SDK 一致） | `ad.` host |
| 错误 | body `code != 0` 失败，消息字段是 **`message`**（不是 `msg`）；HTTP 状态码不可依赖 | 按 `error_response.{code,msg}` → 所有巨量报错退化成 "unknown" |
| App 级接口 | 6 个接口用 `App-Access-Token` 替代 | 未支持 |

## 先做：全部 endpoint 的存在性审计

spec §2.3 只审计了 report 族。本 WP 必须对该 server 调用的**全部 18 个 endpoint** 逐个确认在当前官方文档中是否存在，结论记入 `docs/api-contracts/oceanengine.md`。

尤其需要单独确认的：`2/qianchuan/campaign/list/get/`、`2/qianchuan/report/ad/get/`（巨量千川，可能是独立产品线与版本）、`2/star/report/`、`2/star/task/list/`（巨量星图，同上）、`2/tools/diagnosis/`、`2/dmp/audience/list/`、`2/campaign/read/`、`2/ad/read/`。

不做这一步的风险：修完鉴权后，一部分工具仍然打在不存在的路径上 —— 那等于没修好。

可用官方文档后端接口（公开无需登录）：`https://open.oceanengine.com/skiff/api/doc/client/node/get/`。

## 注意

- 官方文档有一处自相矛盾：【获取Access Token】导语写"通过请求参数传递 Access_Token"，但所有 Header 表格与全部 curl/SDK 示例都是 header。**按 header 实现。**
- `ad.` 与 `api.` 的适用范围**官方零说明**（1053 篇文档 + 246 篇日志均无）。统一用 `api.` 并保留 per-endpoint override；v2 接口在 `api.` 上的可用性标注为待真机回归。
- **以下 token 生命周期事项仅供参考，本 mission 不要求实现** —— 当前代码没有 OAuth 流（只从环境变量读静态 token），FR-004/FR-005 也不覆盖 token 刷新。若将来实现刷新：refresh_token 一次性轮转、刷新后原 token 失效 → 需原子持久化 + 加锁串行；有效期读运行时 `expires_in` 不硬编码（官方正文 30 天与返回示例 7 天矛盾）。
- 需特判：`40102` token 过期可重放、`40103`/`40107` refresh 过期**不可重试**、`40130` 单 advertiser QPS 上限「请避免立即重试」。

# 第二部分：报表迁移 v3.0（原 WP04，因与本 WP 改动同一文件而合并）
# Work Package Prompt: WP04 – 巨量引擎-报表迁移-v3.0

实现 FR-005，覆盖 IC-08。**本 mission 唯一涉及业务语义重写的 WP。**

## 背景

官方公告（预通知 `changelog/1796386957503732` 2024-04-15、正式 `changelog/1798385305745562` 2024-05-07）确认一批接口于 **2024-05-06 下线**，页面已从文档站删除。本仓库命中 5 个：

`2/ad/get/`、`2/campaign/get/`、`2/report/ad/get/`、`2/report/audience/`（整组）、`2/report/creative/get/`；另 `2/report/advertiser/get/` 的 `platform_version` V1 枚举下线。

官方现存 `2/report/*` 仅剩 `site/page/`、`rta_exp/get/`、`rta_cus_exp/get/`，本仓库均未使用。

## 迁移目标

`/open_api/v3.0/report/custom/get/`（同步）+ `/open_api/v3.0/report/custom/config/get/`（查可用维度指标）；大数据量走 `custom/async_task/{create,get,download}/`。

参数结构由旧的 `fields` / `group_by` 平铺，改为 `data_topic` + `dimensions` + `metrics` 三段式，另有 `filters` / `order_by` / `start_time` / `end_time` / `page` / `page_size`。

## 关键决策（需在实现前确定并记录）

工具暴露给模型的入参签名会随之变化。**建议保持现有工具接口稳定、在内部转译到 v3.0**，以免破坏既有用法；若选择把 v3.0 表达能力透出给模型，需在 WP12 同步更新文档。

## 陷阱

官方 Java SDK 最新版（1.1.93，2026-08-12）**仍在发布** `ReportAdGetV2Api` 等已下线接口的类 —— SDK 里有类不等于接口还活着。不要以 SDK 存在性作为接口存活依据。

## 通用约束

1. 签名参与集合必须恒等于发送集合减去 `sign`（WP02 提供通用断言，必须启用）。
2. 签名与发送使用同一字符串对象；业务参数 JSON 只序列化一次并缓存。
3. 契约声明文档中每项结论标注官方出处 URL，区分「官方明文」与「推断」。
4. 官方缺失/矛盾项按 spec.md §8 处理，不得推测填充。
5. 交付需附 wire 层断言：参数名集合、传输位置、timestamp 格式。
