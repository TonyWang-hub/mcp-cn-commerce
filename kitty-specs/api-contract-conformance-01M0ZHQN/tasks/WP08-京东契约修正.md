# Work Package Prompt: WP08 – 京东契约修正

实现 FR-009。`servers/jd/server.py` 覆写了 `_sign` 但走 base `_request`。

## 官方契约 vs 现状

| 项 | 官方（签名已复现验证） | 现状 |
|---|---|---|
| timestamp | `yyyy-MM-dd HH:mm:ss`，或带毫秒时区 `.SSSZ`（如 `2021-05-07 09:20:39.683+0800`）。**容差 6 分钟**（不是 10） | epoch 毫秒 |
| 签名 | `UPPER(MD5(appSecret + Σ(name+value, ASCII升序) + appSecret))` —— secret 首尾各一次 | **HMAC-MD5** |
| 业务参数 | 放 `360buy_param_json`（一个 JSON 字符串参数），**参与签名**且因 `3` 开头排最前 | 放 POST JSON body，**不参与签名** |
| `format` | 官方参数表写"必传"，但**已验证的签名串里没有它**；京东健康版文档写"否" | 发了且没入签 → 签名必错 |
| `sign_method` | 不在公共参数表，md5 默认不传 | 发了 |
| 错误信封 | `error_response.{code, zh_desc, en_desc}` | 读 `msg` → **所有京东报错显示 "unknown"** |
| `access_token` | 普通参数（非 header），参与签名，非授权接口整个省略 | ✅ 名字和位置正确 |
| 网关 | `https://api.jd.com/routerjson`（仅 HTTPS） | ✅ |

## 官方验证向量（WP01 已固化）

官方示例拼接串 → `D70825340F4084360B9362B60DFD7930`。该向量同时坐实：secret 首尾包裹、`360buy_param_json` 参与且排最前、`access_token` 参与、`format` 与 `sign_method` **不参与**、timestamp 用原文字符串、结果大写。

## 注意

- **只实现 md5。** hmacmd5/hmacsha256 的官方期望值穷举 100+ 变体均无法复现（文档数据陈旧），按 spec.md §8 不实现。
- **timestamp 显式带 `+0800`**，不依赖进程时区 —— 官方 Java SDK 用 JVM 默认时区，容器跑 UTC 会有 8 小时偏差直接报错码 8。MCP server 常在容器运行，这条必须落实。
- `360buy_param_json` **只序列化一次并缓存该字符串**，签名和发送用同一对象。官方明文要求「拼接过程中 param_json 里的参数顺序应与请求传入顺序一致」。
- 官方 SDK 的做法是系统参数走 query、`360buy_param_json` 走 `application/x-www-form-urlencoded` 的 POST body，规避 URL 长度上限。建议照此。
- 响应字段**按名取，不要按位置** —— 错误码 62 的官方示例字段顺序是 `zh_desc,en_desc,code`。另需兼容 token 接口的 `{code,msg,requestId}` 信封。
- 待评估（out of scope）：官方将 `routerjson` 标注为"历史接口，逐步迁移"，新网关 SP-API `https://api-cn.jd.com/rest` 走 `X-JOS-*` header 签名。

## 通用约束

1. 签名参与集合必须恒等于发送集合减去 `sign`（WP02 提供通用断言，必须启用）。
2. 签名与发送使用同一字符串对象；业务参数 JSON 只序列化一次并缓存。
3. 契约声明文档中每项结论标注官方出处 URL，区分「官方明文」与「推断」。
4. 官方缺失/矛盾项按 spec.md §8 处理，不得推测填充。
5. 交付需附 wire 层断言：参数名集合、传输位置、timestamp 格式。
