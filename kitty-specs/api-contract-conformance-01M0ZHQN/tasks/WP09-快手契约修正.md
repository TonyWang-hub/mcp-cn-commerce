# Work Package Prompt: WP09 – 快手契约修正

实现 FR-010，覆盖 IC-07。`servers/kuaishou/server.py` 覆写 `_sign` 但走 base `_request`。

## 官方契约 vs 现状（官方 Java SDK 反编译交叉验证）

| 项 | 官方 | 现状 |
|---|---|---|
| 网关 | `https://openapi.kwaixiaodian.com`（备用 `open.kwaixiaodian.com`） | ✅ |
| REST path | `method` 点换斜杠：`open.seller.order.pcursor.list` → `/open/seller/order/pcursor/list` | ❌ `/open/api/order/list` —— `api` 段官方不存在，路径是虚构的 |
| `appkey` | **全小写无下划线** | `app_key` |
| `signMethod` | **驼峰** | `sign_method` |
| `method` | 必填，点分，参与签名 | 没发 |
| `version` | 必填，值 `1` | 没发 |
| `param` | 业务参数打包成**一个 JSON 字符串**放在 `param` 键 | 业务参数当独立 query 参数散发 |
| 签名密钥 | **`signSecret`**（与 appSecret 是两个凭证；appSecret 只用于 OAuth） | ✅ 已用 signSecret |
| 签名 | 排序后 `k=v` 用 `&` 连接，**末尾追加字面量 `&signSecret=<signSecret>`**，MD5 → **小写 hex**（或 HMAC_SHA256 → **Base64 非 hex**） | `secret + kvkv... + secret` → MD5 **大写** |
| timestamp | 毫秒 | ✅ |
| `access_token` | snake_case，普通参数 | ✅ |
| 成功判定 | **`result == 1`**，业务数据在 `data` | 查 `error_response` → **报错完全检测不到**，还会把 `result`/`error_msg` 当数据返回 |

签名参与集合（官方 SDK `SignUtils.getSignParam()`）：必填 `method`/`appkey`/`access_token`，非空则含 `signMethod`/`version`/`timestamp`/`param`；排除 `sign` 与 byte[]。排序用 TreeMap（跳过 null）。值**不做 URL 编码**参与签名，编码只在最终发送时做。

## 注意

- POST 时官方客户端**只把 `appkey` 留在 query string**，并从 body 中移除它，其余全部走 urlencoded form body。Content-Type 仅支持 `application/x-www-form-urlencoded`。
- GET/POST 是**逐 API 决定**的（官方 SDK 453 个请求类中 233 GET / 219 POST），不能统一。
- 官方文档 §4 示例 URL 的 anchor 文本是小写、href 是大写，自相矛盾；官方 SDK 用 `md5Hex` → **以小写为准**。
- `uid` 是历史参数，当前官方 SDK 已无此字段，**不要发**。
- 第三方 Python SDK 有 `/open/open/...` 双前缀 bug 和把 `result` 当 payload 的信封误解，**不要参考它**。

## 通用约束

1. 签名参与集合必须恒等于发送集合减去 `sign`（WP02 提供通用断言，必须启用）。
2. 签名与发送使用同一字符串对象；业务参数 JSON 只序列化一次并缓存。
3. 契约声明文档中每项结论标注官方出处 URL，区分「官方明文」与「推断」。
4. 官方缺失/矛盾项按 spec.md §8 处理，不得推测填充。
5. 交付需附 wire 层断言：参数名集合、传输位置、timestamp 格式。
